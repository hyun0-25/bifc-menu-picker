# 식당 목록 작성 기준 (PLAN 작업 3)

> `data/restaurants.json` 27곳을 어떻게 모았고 값을 어떻게 정했는지 적은 기록이다. 조사일: 2026-11-03

## 1. 출처와 선정 과정

- **출처**: 카카오맵 장소 상세 페이지. 가게마다 `source`에 주소를 남겼다. (예: https://place.map.kakao.com/27485313)
- **과정**
  1. "문현동 한식·중식·일식·양식·고기·분식·쌀국수·돈까스", "BIFC 맛집"으로 검색 → 129곳
  2. BIFC에서 도보 15분 이내 → 56곳
  3. 메뉴 가격이 공개된 곳 → 39곳 (가격을 모르는 가게는 예산 조건으로 거를 수 없어 제외)
  4. 카페·술집(안주 위주)·100g 단위 판매 가게를 빼고, 메뉴 종류가 고르게 섞이도록 **27곳** 선정
- 모든 가게는 조사일 기준 카카오맵에서 영업 중으로 표시되었다.

## 2. 항목별 값 정하는 기준

| 항목 | 기준 |
|---|---|
| `pricePerPerson` | 카카오맵 메뉴판의 앞 8개 가격의 **중간값**을 500원 단위로 반올림. 뷔페는 평일 성인 점심 가격(더스타뷔페 39,000원), 애슐리퀸즈는 평일 성인 런치 가격(19,900원) |
| `walkMinutes` | BIFC몰(문현금융로 40) 위치를 기준점으로 한 직선거리 × 1.3(길이 굽는 정도) ÷ 분당 67m(시속 약 4km), 올림. 최소 1분 |
| `cuisine` | 카카오맵 분류를 8가지로 옮김: 돈까스·우동·라멘·아부라소바 → 일식 / 삼계탕·국밥·막국수·기사식당 → 한식 / 닭갈비 → 고기 / 이탈리안·햄버거 → 양식 / 태국음식 → 아시안 / 뷔페·패밀리레스토랑 → 기타 |
| `groupSeating` | 카카오맵 "좌석 옵션"에 **단체석**이 표시된 가게만 `true` |
| `hasRoom` | "프라이빗룸"이 표시된 가게만 `true`. 표시가 없으면 **없다고 단정하지 않고** `"정보 없음"` |
| `reservation` | 카카오 예약을 받는 가게만 `"가능"`. 그 외는 `"정보 없음"` (불가로 확인된 가게 없음) |
| `maxCapacity`, `roomCapacity` | 카카오맵에 공개된 가게가 없어 모두 `"정보 없음"` |

## 2-1. 차량 전용 가게 (도보 15분 밖, 24곳)

팀 회식에서 차량으로 갈 곳을 위해 r28~r51을 추가했다. 조사일 2026-11-03.
- 찾는 방법: 카카오맵 검색(문현·전포·부전·범일·대연동 일대 고기·한식·양식·일식)으로 모은 뒤, BIFC에서 도보 15분 밖·차량 어림 12분 이내이고, 영업 중이며, 메뉴 가격이 공개되고, **단체석·프라이빗룸·카카오 예약 중 하나가 표시된** 곳만 골랐다. 메뉴 종류가 섞이도록 고기 11, 한식 8, 양식 3, 일식 2곳.
- 횟집·족발·보쌈처럼 한 접시가 여러 명 몫이라 `1인 가격`이 부정확해지는 가게는 뺐다. 고깃집 가격은 메뉴판 대표값이라 실제 1인 비용과 다를 수 있다.
- `driveMinutes`는 직선거리로 어림한 값이다 (실제 길찾기 아님).
- 이 가게들은 도보로 찾을 때는 나오지 않는다 (도보 15분 초과).

## 3. 알려진 한계

| 항목 | 현황 |
|---|---|
| 단체석 표시 | 27곳 중 9곳 |
| 룸 확인 | 2곳 (성해루, 더스타뷔페) |
| 예약 가능 확인 | 2곳 (미도방 BIFC몰 본점, 하루키) — 둘 다 단체석 표시는 없음 |

그래서 **5명 이상 회식**은 단체석 표시가 있는 9곳 안에서만 추천되고, **룸이나 예약이 필요한 회식**은 후보가 거의 없다 (docs/test-results.md의 6·7·8·10번 질문이 0곳).

## 4. 값을 채우는 방법 (작성자)

가게에 전화하거나 방문해서 확인한 값만 파일에 고쳐 적는다. 확인 못 한 값은 짐작하지 않고 `"정보 없음"`으로 둔다.

우선 확인하면 효과가 큰 가게:

1. 단체석 표시가 있는 9곳(마루카츠, 주왕산삼계탕, 성해루, 루암밋타이, 작은딸, 봉평메밀막국수, 마산식당, 파스타빌라, 더스타뷔페): 최대 인원, 룸 유무·룸 인원, 예약 가능 여부
2. 회식용으로 좋아 보이는 가게: 룸 유무와 예약 가능 여부

고친 뒤에는 `npm test`로 형식을 확인하고, `EVAL_DATA=real npm run eval`로 다시 점검한다.

## 5. 자동 갱신 (`npm run refresh:data`)

목록은 파일로 두되, 값을 최신으로 맞추는 일은 도구가 한다. 가끔(예: 한 달에 한 번, 배포 전) 실행하면 된다.

```bash
npm run refresh:data               # 미리보기: 무엇이 바뀌는지 보고서만 (파일은 안 고침)
npm run refresh:data -- --write    # 보고서의 "바뀌는 값"을 data/restaurants.json에 반영
npm run refresh:data -- --discover # 목록에 없는 새 가게도 찾기 (.env에 KAKAO_REST_API_KEY 필요)
```

반영 뒤에는 `npm test`로 형식을 확인하고 커밋한 다음, Vercel에는 **다시 배포**해야 반영된다.

**자동으로 바꾸는 값**: 가게 이름, 대표 메뉴, 대표 가격(2장의 기준), 도보 시간, 그리고 카카오맵에 **새로 생긴** 단체석·프라이빗룸·카카오 예약.

**자동으로 바꾸지 않는 값** (사람이 확인했을 수 있어서)
- 최대 인원, 룸 인원: 어떤 경우에도 그대로 둔다.
- 이미 확인한 룸·예약·단체석: 카카오맵에서 표시가 사라져도 지우지 않고 "확인 필요"로만 알린다.
- `priceBasis`가 적힌 가게(뷔페처럼 가격 기준을 사람이 정한 곳): 가격·메뉴를 건드리지 않는다.

**자동으로 지우지 않고 알리기만 하는 것**: 영업 상태가 정상이 아닌 가게(폐업 의심), 도보 15분을 넘는 가게, 1년 넘게 갱신되지 않은 정보, 가격이 공개되지 않아 갱신 못 한 가게, 가격이 20% 이상 달라진 가게.

**새 가게 찾기(`--discover`)**: 카카오 공식 검색(음식점, BIFC 반경 1km)으로 목록에 없는 가게를 가까운 순으로 보여 준다. 목록에 넣을지는 사람이 고른다. 메뉴 가격이 공개되지 않은 가게는 예산 조건을 지킬 수 없어 넣지 않는다. 카카오 개발자 사이트에서 REST API 키를 발급받아 `.env`에 `KAKAO_REST_API_KEY`로 넣어야 한다. (이 기능은 키가 없어 실제 호출은 시험하지 못했고, 결과를 고르는 부분만 자동 점검으로 확인했다.)

**알아 둘 점**: 가게 상세(메뉴·가격·영업 상태)는 카카오맵 화면이 쓰는 비공식 주소에서 읽는다. 사람이 가끔 쓰는 점검 도구로만 쓰고(요청 사이 0.4초 간격), 앱이 사용자 요청마다 호출하지 않는다. 카카오맵이 이 주소를 바꾸면 도구가 "정보를 읽지 못했어요"라고 알리므로, 그때는 도구를 고쳐야 한다.
